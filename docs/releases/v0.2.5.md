# Airdrop for Windows 0.2.5 — 文件拖放 / File drag and drop

作者 / Author: **Dy1an-Zou** · **实验预览版 / Experimental preview**

## 中文

- 对方确认接收成功后，自动移除本次待发送文件；失败、拒收或取消时保留，方便重试。
- 从资源管理器把一个或多个文件拖到主窗口或发送窗口，即可加入待发送。
- 已接收文件支持单个、多选拖出到支持文件拖放的窗口。使用复制方式，原文件和接收记录保留。
- 保留空白处框选、Ctrl/Shift 多选、双击打开和右键操作。

本次更新仅涉及桌面交互，网卡兼容范围不变。MT7925 与 RTL8852CE 仍使用各自对应的运行包；RTL8852CE 仍为未经实机验收的社区预览。

### 验证范围与已知限制

- 文件交互 34 项、既有界面 10 项、语言 3 项检查通过；随包应用检查包含本机 HTTPS/CPIO 文件回环传输。3 个针对发送队列的错误变体被检出。两种安装包均做内嵌文件核验。
- 本机 MT7925 已更新至 0.2.5，重启后确认驱动、无线连接和接收服务就绪。**本轮未重新验证手机双向传输，也未实际用鼠标拖入 Codex 等外部应用。** 实施检查不等于跨应用实测。
- 本轮曾遇到 MT7925 缓冲区分配失败；随后重启又因测试签名未生效出现 Code 52。恢复测试签名并再次重启后，服务启动成功。根本的分配问题没有在本版驱动中修复；再次遇到时请提供脱敏日志。测试签名必须在当前启动中生效，仅安装测试证书不代表驱动能加载。
- RTL 的实际安装、发现、收发、关闭重开、睡眠恢复和不同 OEM 硬件仍待验证。两种新 EXE 安装器未做新电脑安装或真实卸载验收。
- 暂不支持直接拖入文件夹。「仅限联系人」、验证码配对和 30 天临时联系人仍不支持，使用「所有人，10 分钟」。所有 Apple 型号、系统版本、文件类型和长期稳定性没有全面验证。

反馈请提交 [Issue](https://github.com/Dy1an-Zou/Airdrop-for-Windows/issues)，附网卡硬件 ID、Windows/Apple 系统版本和失败步骤。上传日志前去除个人信息，不上传私钥或私人文件。

## English

- Files leave the outgoing queue once the receiving device confirms success. Failed, declined and cancelled transfers keep their files for retry.
- Drop one or more files from File Explorer into the main window or send window to queue them.
- Drag received files, including multiple selected files, into applications that accept file drops. Dragging copies files and preserves the originals and receive history.
- Blank-space marquee selection, Ctrl/Shift selection, double-click and context-menu actions are retained.

This update changes desktop interactions only. Hardware compatibility is unchanged. MT7925 and RTL8852CE require their corresponding runtime packages; RTL8852CE remains a community preview without hardware acceptance testing.

### Downloads and compatibility

| Package | Supported setup |
| --- | --- |
| `Airdrop-for-Windows-0.2.5-MT7925-Setup-x64.exe` | Dedicated MT7925 with the matching experimental driver; hardware ID `PCI\VEN_14C3&DEV_7925&SUBSYS_60001A3B&REV_00`. Previous bidirectional image transfers were confirmed on the author's PC. This round verified the local 0.2.5 update and receiver startup after reboot. |
| `Airdrop-for-Windows-0.2.5-RTL8852CE-Preview-Setup-x64.exe` | Dedicated RTL8852CE PCIe, `PCI\VEN_10EC&DEV_C852`. **Still not tested on RTL hardware by this project.** Native components are unchanged from 0.2.4; only the desktop app and installer are updated. |
| `Airdrop-for-Windows-0.2.5-Source.zip` | Project sources, tests and four pinned corresponding-source archives for the RTL upstream components. GitHub's automatic source archives omit those four extra archives. |

**Choose the installer for your adapter. Cross-backend upgrades are rejected.** Intel, Broadcom, RTL8852AE/BE, Realtek USB and other unlisted hardware are unsupported.

Requires Windows 11 x64 build 26100+, .NET Desktop Runtime 10 x64, and a dedicated adapter with the matching experimental driver already configured. RTL additionally requires the matching Visual C++ runtime and Lock pages in memory privilege; see the [RTL setup guide](https://github.com/Dy1an-Zou/Airdrop-for-Windows/blob/v0.2.5/docs/RTL8852CE.md). Setup **does not install drivers, change test-signing or other security settings, or reboot Windows**. Exit the app from the tray before updating. Settings, history and received files are preserved. [Installation guide](https://github.com/Dy1an-Zou/Airdrop-for-Windows/blob/v0.2.5/docs/INSTALL.md#english)

### Verification and known limits

- Passed 34 file-interaction checks, 10 existing UI checks and 3 language checks. Packaged application checks include local HTTPS/CPIO file-transfer loopback. Three targeted outgoing-queue fault variants were detected. Embedded files in both installers were verified.
- The local MT7925 installation was updated to 0.2.5; driver, radio and receiver startup were confirmed after reboot. **Phone transfers and actual mouse drops into Codex or other applications were not repeated this round.** Implementation checks are not cross-application acceptance tests.
- MT7925 buffer allocation failed during this round. A subsequent reboot exposed Code 52 because test signing was inactive. Restoring test signing and rebooting again allowed the receiver to start. The underlying allocation issue is not fixed in this release's driver; provide sanitized logs if it recurs. Test signing must be active in the current boot; installing a test certificate alone does not make the driver loadable.
- RTL installation, discovery, transfers, shutdown/restart, sleep/wake and OEM variants remain untested. Neither new EXE installer has fresh-PC installation or live uninstall acceptance.
- Dropping folders, Contacts Only, verification-code pairing and 30-day temporary contacts are not implemented. Use Everyone for 10 Minutes. Coverage of Apple models, OS versions, file types and long-running stability is incomplete.

Open an [issue](https://github.com/Dy1an-Zou/Airdrop-for-Windows/issues) with hardware ID, Windows/Apple OS versions and reproduction steps. Remove personal information from logs; never upload private keys or personal files.
